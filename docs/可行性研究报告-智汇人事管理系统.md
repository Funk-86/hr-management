1.研究背景和目的
1.1研究背景
随着企业规模扩大与用工形式多样化，人力资源管理涉及的组织架构维护、员工档案管理、日常考勤统计、请假审批流转、薪资记录等业务日益繁杂。传统依赖 Excel 表格、纸质登记的方式存在数据分散、统计滞后、权限难以控制、历史记录不易追溯等问题，已难以满足中小企业对人事管理规范化、信息化的需求[12]。

近年来，Spring Boot、前后端分离、RESTful API、JWT 无状态认证等 Java Web 技术日趋成熟[3,14]；Vue 3、Vite、组件化 UI 框架等前端技术也为企业管理系统提供了高效的可视化交互能力[3,16]。企业对人力资源数字化转型的需求持续增长，建设一套面向中小企业的 HR 一体化管理平台具有现实背景与广泛的应用场景[4,12]。

本课题已设计并实现的智汇人事管理系统（hr-management），面向中小型企业及部门级人事管理场景，采用 B/S 架构[4]，后端提供 REST API，前端基于 Vue Vben Admin 构建 Web 管理界面，涵盖组织架构、员工档案、RBAC 权限认证、工作台、考勤打卡、请假审批、薪资管理等核心业务，实现人事信息的集中存储、规范流转与高效查询。

当前许多中小企业虽可使用大型 HR SaaS 产品，但存在成本高、功能冗余、定制困难等问题[12]；而完全手工管理又效率低下。因此，设计并实现一套功能适中、结构清晰、前后端完整、可实际部署的自主人事管理系统，具有明确的必要性与实践价值。

1.2研究目的
本研究旨在设计并实现一套基于 Spring Boot 与 Vue 前后端分离架构的中小企业人力资源管理系统，具体目的如下：
1.业务整合：将部门、岗位、员工、考勤、请假、薪资等分散业务整合于统一平台，减少重复录入与信息孤岛。
2.流程规范：通过系统化的打卡、请假申请与审批状态管理，规范人事日常操作流程。
3.安全可控：基于 RBAC 角色权限模型[10,13]与 JWT 认证机制[9,11]，结合按角色划分的数据访问范围，保障系统访问安全与数据隔离。
4.技术实践：综合运用 Spring Boot 4、MyBatis-Plus、MySQL、Spring Security、Vue 3、Vben Admin 等主流技术[2,3,14,15,16]，完成从需求分析、数据库设计[1]到全栈实现的完整开发流程。
5.可部署交付：提供开发、生产及 Docker 容器化部署方案，使系统具备可演示、可验收、可扩展的工程化基础。

本课题将在借鉴现有研究成果[3,4,9]的基础上，设计并实现一套结构清晰、模块完整、可实际部署测试的人事管理系统。

3.可行性分析
3.1技术可行性
从技术角度分析，本系统已具备充分开发条件，且核心功能均已实现：
1.后端框架：采用 Java 17 与 Spring Boot 4.1[2,14]，生态成熟，文档完善，适合2企业级 Web 应用开发。
2.持久层方案：使用 MyBatis-Plus 3.5 操作 MySQL 8.0 数据库[1,15]，支持逻辑删除、自动填充、条件构造器，显著提升开发效率。
3.安全认证：Spring Security 结合 JWT（jjwt 0.12.6）实现无状态登录认证[9,11]；密码采用 BCrypt 加密存储。
4.前端框架：基于 Vue 3 + Vite + Pinia + Ant Design Vue，采用 Vben Admin 管理模板[3,16]，已实现工作台、组织、员工、考勤、请假、薪资等页面。
5.接口文档：开发环境集成 SpringDoc（Swagger UI），便于接口调试与系统说明撰写；生产环境默认关闭。
6.容器化部署：提供 Docker Compose 方案（MySQL + Spring Boot + Nginx），支持同域前后端访问与快速验收。
7.开发者能力：课题负责人已掌握 Java 面向对象编程[2]、数据库设计[1]、Maven 项目管理、REST API 及 Vue 前端开发等基础，具备独立完成本系统全栈开发的能力。

3.3操作可行性
1.用户角色清晰：系统预设超级管理员、HR 管理员、部门经理、普通员工四类角色，符合一般企业分工习惯[10,13]。
2.界面友好：前端采用 Ant Design Vue 组件库，提供表格、表单、日历、统计卡片等常用交互；工作台按角色展示考勤月历、待审批事项与快捷入口。
3.接口规范：RESTful API 统一前缀 /api，响应结构规范（code / data / message），便于前后端联调及后续扩展移动端。
4.学习成本低：员工端仅需完成登录、打卡、提交请假等少量操作[6,8]；HR 端以表单维护与列表查询为主，易于培训上手。
5.部署简单：Spring Boot 内嵌 Tomcat，可打包为 JAR 一键启动[14]；亦可通过 deploy/start.ps1 或 start.sh 一键构建前端并启动 Docker 环境。
4.研究内容
4.1主要研究内容
系统整体采用 B/S 架构、前后端分离部署[3,4]。浏览器访问 Vue 页面，业务请求统一走 `/api` 前缀的 REST 接口，由 Spring Boot 单体应用处理并读写 MySQL 数据库。

后端按业务划分子包（`auth`、`department`、`employee`、`attendance`、`leave`、`salary`、`dashboard` 等），各模块内部遵循 Controller—Service—Mapper—Entity 分层；入参、出参分别用 DTO、VO 与实体类区分。认证授权由 Spring Security 配合 JWT 完成，列表查询在 Service 层按角色拼接数据范围条件。公共能力包括统一响应体（code / data / message）、全局异常处理、实体基类逻辑删除及创建/更新时间自动填充等。

前端基于 Vue 3 与 Vben Admin（Ant Design Vue），在 `apps/web-antd` 中按 HR 业务拆页面，接口调用集中在 API 封装层，路由与侧边栏菜单随登录角色动态加载。开发环境通过 Vite 代理访问后端，生产环境可由 Nginx 同域反代前后端。

4.2主要创新点
本系统创新点主要体现在以下方面：
角色化数据权限与 RBAC 融合：在单体应用中同时实现用户—角色—权限—菜单链路与 Service 层数据范围过滤，使普通员工、部门经理、HR 在同一套接口下获得不同数据视图，兼顾安全性与实现简洁性[9,10,13]。
员工入职与账号一体化建档：员工创建时在同一事务内自动创建登录用户、BCrypt 加密密码并绑定角色，减少 HR 重复操作，保证 hr_employee 与 sys_user 数据一致。
多场景考勤打卡设计：支持员工自助打卡、超级管理员代他人打卡、HR 补录历史考勤；打卡逻辑兼容“先补录空记录再更新”场景，避免唯一索引冲突，提高系统健壮性[6]。
请假业务规则完备化：实现请假时间段冲突检测、假期类型最大天数校验、审批/驳回/撤销状态机，并按角色过滤待办与历史记录，贴近实际审批流程[6,7,8]。
角色化工作台：前端工作台根据登录角色动态展示考勤月历、统计指标与快捷入口（如纯超管不展示个人日历），提升不同岗位的使用体验。

轻量级全栈可部署架构：不引入微服务与消息队列，采用 Spring Boot 单体 + Vue 前端 + Nginx 反代 + Docker Compose 的组合，降低学习、演示与二次开发门槛，适合教学验收与中小企业试用[12]。

5.实施方案与技术路线
5.1研究方法
本课题采用管理信息系统的一般研究方法，结合软件工程规范与面向对象分析设计方法，按“调研—分析—设计—实现—测试”五个阶段推进，具体如下。

（1）需求调研
通过文献查阅、网络资料搜集及对中小企业人事管理流程的梳理，明确系统建设背景与目标用户。重点调研组织架构维护、员工档案管理、考勤打卡、请假审批、薪资记录等日常业务，归纳四类角色（员工、部门经理、HR 管理员、超级管理员）的操作场景与权限差异。结合同类 HR 系统功能对比[4,12]，确定本系统“功能适中、全栈可部署”的定位，形成需求清单与用例描述，作为后续分析与设计的输入。

（2）系统分析
在需求调研基础上，采用面向对象方法对系统进行结构化分析。绘制用例图，描述各角色与登录、工作台、组织管理、员工管理、考勤管理、请假管理、薪资管理等用例之间的关联；编写用例说明，明确前置条件、基本流程与异常处理。对考勤打卡、请假审批等核心流程绘制活动图，描述业务步骤与分支判断；对请假申请等具有多种状态的对象绘制状态图，说明待审批、已通过、已驳回、已撤销等状态转换关系。通过上述模型将自然语言需求转化为可设计、可实现的形式化描述。

（3）系统设计
系统分析成果基础上开展总体设计与详细设计。采用 B/S 前后端分离架构，后端按 Controller—Service—Mapper 分层，前端按业务模块组织页面与 API 封装。运用面向对象方法绘制类图，描述实体类、业务类及主要属性与关联关系；对登录认证、请假审批、考勤打卡等关键交互绘制时序图，说明前后端与数据库之间的调用顺序。数据库设计方面，完成 E-R 概念设计并转换为 MySQL 物理表结构[1]，涵盖部门、岗位、员工、用户、角色、权限、考勤、请假、薪资等核心表，编写 schema.sql 初始化脚本，保证表间关联清晰、支持逻辑删除与审计字段。

（4）系统实现
按照“后端基础模块 → 核心业务模块 → 前端界面 → 部署联调”的顺序迭代实现。后端基于 Spring Boot 搭建工程，集成 Spring Security 与 JWT 实现认证授权，使用 MyBatis-Plus 完成数据访问，逐模块实现 REST 接口；前端基于 Vue 与 Vben Admin 管理框架开发各业务页面，通过 axios 调用后端 API 并完成角色化菜单展示。实现过程中遵循统一响应格式与全局异常处理，区分开发环境与生产环境配置，并提供 Docker Compose 与 Nginx 部署方案，保证系统可运行、可演示、可验收。

（5）系统测试
系统实现完成后开展多层次测试。接口层使用 Swagger 与 Postman 对登录、员工、考勤、请假、薪资等 API 进行功能测试；业务层按员工、经理、HR、超管四类账号进行端到端场景测试，验证数据权限隔离与审批流程；异常场景测试包括重复打卡、请假时间冲突、越权访问等。在 Docker 环境下进行部署测试，确认数据库初始化、前后端联调及一键启动脚本可用。根据测试结果修复缺陷，形成测试用例记录与测试报告，为论文撰写与答辩演示提供依据。

5.2技术路线
本系统采用前后端分离的 B/S 架构，选用成熟开源技术栈进行开发，主要开发工具与技术如下。
类别	选用工具/技术	选型理由
集成开发环境	IntelliJ IDEA、VS Code	分别适用于 Java 后端与 Vue 前端开发，调试与插件生态完善
版本管理	Git	便于代码版本追踪与阶段性备份
后端语言	Java	面向对象特性清晰，企业级应用广泛，利于分层架构实现
后端框架	Spring Boot	简化配置与部署，内嵌 Web 容器，适合快速构建 REST 服务
安全框架	Spring Security、JWT	满足前后端分离场景下的无状态认证与接口鉴权需求
持久层框架	MyBatis-Plus	在 MyBatis 基础上提供通用 CRUD 与条件构造，提高开发效率
数据库	MySQL	关系型存储，事务支持完善，适合人事类结构化数据管理
前端框架	Vue、Vite	组件化开发，构建速度快，社区活跃
前端 UI	Ant Design Vue、Vben Admin	提供表格、表单、布局等成熟组件，缩短管理后台界面开发周期
状态管理	Pinia	轻量简洁，便于管理登录态与用户信息
接口调试	Postman、Swagger	便于接口文档生成与联调测试
数据库管理	Navicat 或 MySQL Workbench	辅助表结构设计与数据验证
构建工具	Maven、pnpm	分别管理后端依赖与前端 monorepo 依赖
Web 服务器	Nginx	生产环境托管前端静态资源并反向代理后端 API
容器化	Docker、Docker Compose	一键启动 MySQL、后端与 Nginx，便于演示与验收
技术路线流程：需求分析与 UML 建模 → 数据库设计 → Spring Boot 后端开发（认证 → 组织 → 员工 → 考勤 → 请假 → 薪资 → 工作台）→ Vue 前端页面开发与联调 → 系统测试 → Docker/Nginx 部署 → 论文撰写与答辩准备。

6.推广及应用价值
6.1 经济效益
本系统面向中小企业及部门级人事管理场景，可在以下方面产生经济价值：
降低管理成本：将员工档案、考勤、请假、薪资等信息集中管理，减少人工统计、Excel 维护与重复录入，节省 HR 与管理人员的时间成本[4,12]。
减少软件采购支出：相比按年订阅的商业 HR SaaS 产品，本系统基于开源技术栈自主建设，无需支付高额许可费用，适合预算有限的中小企业与创业团队试用。
提高数据准确性：系统内置打卡规则、请假冲突校验、审批状态约束等，降低人为差错导致的考勤纠纷与统计偏差，间接减少管理损失[6,8]。
6.2 社会效益
促进管理规范化：通过信息化手段固化打卡、请假、审批流程，推动企业人事管理由经验驱动向制度驱动转变[5,8]。
保障信息安全：基于 RBAC 与 JWT 认证机制，结合按角色划分的数据访问范围，避免敏感人事数据被越权查看[9,10]。
服务教学与人才培养：本课题作为计算机专业毕业设计实践，将软件工程、数据库、Web 开发等课程知识应用于真实业务，具有示范与推广意义，有助于培养具备全栈开发能力的技术人才[2,3]。

6.3 推广策略
校内推广：将源代码与文档在校内共享，供后续学生参考、二次开发或作为课程设计案例。
开源与文档化：完善 README、部署指南与 API 说明，降低他人部署与二次开发门槛。
小范围试点：在中小企业、创业团队或实验室环境中进行小范围试用，收集反馈并迭代优化。
功能扩展：逐步增加移动端打卡、消息通知、报表导出、操作审计等能力，提升实用性与推广吸引力[7]。

6.4 长期价值
可扩展平台：当前系统采用模块化单体架构，后续可在不改变整体结构的前提下扩展薪酬核算规则、绩效考核、招聘管理等子模块[4,5]。
数据资产积累：系统运行过程中持续积累组织、出勤、请假、薪资等数据，为人员结构分析、出勤率统计及管理决策提供长期数据基础[6,7]。
技术沉淀：项目形成的前后端分离开发模式、权限设计方案与 Docker 部署经验，可复用于其他企业管理信息系统建设，具有持续参考价值。
可以从经济效益、社会效益、推广策略、长期价值等方面进行分析。
