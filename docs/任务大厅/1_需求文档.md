# 需求文档：任务大厅

## 1. 背景与目标

在现有「指派式任务」（创建时指定执行人，可多人协作）之外，新增 **任务大厅**：由部门经理 / HR 向本部门发布可抢单任务；发布时可选 **独占 1 人** 或 **多人协作（明确人数 N）**；员工从大厅接取；完成后评分产生奖金，纳入当月工资核算。

**目标**

- 提高任务分发灵活性（开放认领，而非必须指定人）
- 发布时可配置协作人数（1 = 独占，N = 需 N 人协作）
- 用难度星级、奖金与评分驱动完成质量
- 与现有指派任务 **并存**，互不影响

## 2. 角色与权限

| 动作 | SUPER_ADMIN | HR_ADMIN | DEPT_MANAGER | EMPLOYEE |
|------|:-----------:|:--------:|:------------:|:--------:|
| 发布 / 编辑开放中大厅任务 | ✗ | ✓ | ✓（仅本部门） | ✗ |
| 浏览本部门大厅 | ✓ | ✓ | ✓ | ✓（本部门） |
| 接取 / 放弃 | ✗* | ✗* | ✗* | ✓（需绑定员工且本部门） |
| 强制收回 | ✓ | ✓ | ✓（本部门任务） | ✗ |
| 完成后评分 | ✗ | ✓ | ✓（本部门） | ✗ |
| 选择逾期/未完成处理策略 | ✗ | ✓ | ✓ | ✗ |

\* 大厅接取仅限 `EMPLOYEE` 角色登录态。超管 / HR / 经理如需自己做任务，走原有指派任务或切换员工账号。

## 3. 与现有任务的关系

| 维度 | 指派任务（现有） | 大厅任务（新增） |
|------|------------------|------------------|
| 模式 | `claim_mode = ASSIGNED` | `claim_mode = OPEN` |
| 执行人 | 创建时 **指定** 具体人，可多人 | 开放认领；发布时定 **名额** `claim_quota`（1=独占，N=协作） |
| 入口 | 任务管理 | 任务大厅 + 任务管理（已认领后可在「我负责的」看到） |
| 发布人 | 超管 / HR / 经理 | **仅 HR / 经理** |

## 4. 功能需求

### 4.1 发布大厅任务

发布人填写：

- 标题、内容、截止时间（可选）
- **难度**：1～5 星（必填）
- **协作名额 `claimQuota`**（必填）：
  - `1`：独占一人（满员即不可再接）
  - `N`（N≥2）：多人协作，需凑满 N 人；列表展示「已接 x / 需 N」
- **建议奖金**（选填，展示用；入账以 **每人评分** 为准）
- **逾期/未完成处理策略**（必填，三选一）：
  - `MARK_ONLY`：仅标记
  - `ZERO_BONUS`：逾期/未完成关闭时，相关执行人奖金按 0
  - `DEDUCT`：发布时 **手填扣款金额**（元）；对适用的未完成执行人记扣款（见 §4.5）
- 所属部门：经理固定本部门；HR 可选部门

### 4.2 任务大厅（本部门）

- 列表：标题、难度星级、建议奖金、**名额（已接/需）**、截止时间、发布人、状态
- 仅显示本部门，且仍可接取的任务（已接人数 < `claimQuota`，主状态为开放中）
- 「接取」：名额未满则可接；已满或已接过则失败提示

### 4.3 接取 / 放弃 / 强制收回

- **接取**：事务保证不超过 `claimQuota`；同一员工不可重复接取同一任务；满员后任务进入进行中（或保持进行中且大厅不再展示）
- **放弃**：任一已接取人可放弃自己的名额 → 已接人数 -1；若因此低于名额，任务重新可被接取（回大厅开放）；需填原因
- **强制收回**：HR / 本部门经理 / 超管  
  - 可收回 **某一执行人** 或 **整任务**  
  - 整任务：回大厅（清空全部认领）或关闭（应用逾期策略）；需填原因

### 4.4 执行与完成

- 每人独立进度（复用 `hr_task_assignee`）
- **主任务完成条件**：已接满 `claimQuota` 且 **所有已接取执行人均完成**（与现有多人指派一致）
- 未满员时：允许先做进度，但主任务不得标完成（或产品约定：满员前也可各自完成，主任务等满员且全员完成——**一期采用：必须先满员，再按全员完成**）

### 4.5 评分与工资

- **口径**：各执行人 **完成 + 评分** 后的 `score_bonus` 计入各自当月薪
- 评分人：HR / 本部门经理（按人评分）
- `ZERO_BONUS`：关闭时未完成（或策略适用）的执行人奖金为 0
- `DEDUCT`：关闭时对未完成执行人各记一笔扣款（金额 = 发布时手填的 `deductAmount`）；已完成并评分者不受扣款（除非产品改为整任务扣——**一期：仅扣未完成的执行人**）

### 4.6 详情展示

- 难度、建议奖金、名额（已接/需）、执行人列表
- 逾期策略说明 + 扣款额
- 放弃 / 收回原因与时间线
- 各人评分与奖金

## 5. 状态机

```
开放中(OPEN, claimed < quota)
        ↓ 有人接取（未满员仍 OPEN，大厅可见）
        ↓ 满员 claimed == quota
进行中(IN_PROGRESS)（大厅不再展示为可接）
        ↓ 全员完成
已完成(DONE) → 评分 → 关闭

任一人放弃且 claimed < quota → 回到可接取（OPEN）
强制收回整单回大厅 → OPEN（清空认领）
强制收回/逾期关闭 → CLOSED（应用策略）
```

## 6. 验收标准（AC）

| ID | 描述 |
|----|------|
| AC-001 | HR、部门经理可发布本部门大厅任务；超管不能发布 |
| AC-002 | 发布时必选难度 1～5、协作名额 ≥1、逾期策略；DEDUCT 必填扣款额 > 0 |
| AC-003 | 员工仅能看到本部门仍有空位的开放任务 |
| AC-004 | 并发接取不会超过 `claimQuota`；超限或重复接取有明确提示 |
| AC-005 | `claimQuota=1` 时第二人接取失败；`claimQuota=N` 时可接满 N 人 |
| AC-006 | 接取人可放弃自己的名额；名额释放后他人可接；记录原因 |
| AC-007 | HR / 本部门经理 / 超管可强制收回，记录原因 |
| AC-008 | 完成后按人评分产生奖金，进入当月薪 |
| AC-009 | 逾期/未完成关闭按策略：仅标记 / 奖金 0 / 对未完成人手填扣款 |
| AC-010 | 详情展示难度、名额、策略、扣款、执行人与时间线 |
| AC-011 | 原有指派任务不受影响 |

## 7. 非功能需求

- 接取：事务 + 条件更新/行锁，保证不超过名额且防重复
- 关键写操作记日志
- 通知：上架、接取、满员、放弃、收回、评分

## 8. 已确认决策记录

| 问题 | 结论 |
|------|------|
| 与指派任务 | 并存 |
| 工资口径 | 完成 + 评分奖金（按人） |
| 逾期处理 | 发布时三选一；DEDUCT 手填金额 |
| 放弃 | 可以（释放自己名额） |
| 强制收回 | HR、部门经理、超管 |
| 大厅范围 | 本部门 |
| 发布权限 | 仅 HR、经理 |
| 接取人数 | **发布时选择：1=独占，N=协作（明确几人）** |
