# 技术设计文档：任务大厅

## 0. 设计概要

* **功能描述**：大厅开放认领任务；发布时配置 **协作名额**（1=独占，N=多人协作）；难度星级；完成按人评分计奖；逾期策略含手填扣款。
* **影响范围**：`module/task`、`module/salary`、权限种子、前端大厅页。
* **技术难点**：名额并发控制（不超过 `claim_quota`、防重复接取）；满员/释放名额状态切换；多人扣款流水。
* **依赖关系**：现有 `hr_task` / `hr_task_assignee` / 评分字典 / 薪资汇总 / 通知。

## 1. 架构概览

```mermaid
sequenceDiagram
    participant M as 经理/HR
    participant FE as 前端任务大厅
    participant API as Task API
    participant DB as MySQL

    M->>FE: 发布(claimQuota=1或N, 难度, 策略)
    FE->>API: POST /tasks/hall
    API->>DB: claim_mode=OPEN, claim_quota=N, status=0

    FE->>API: POST /tasks/{id}/claim
    API->>DB: FOR UPDATE 计有效认领数
    alt count < quota 且未接过
        API->>DB: insert assignee; count==quota 则 status=1
        API-->>FE: 成功（返回已接/名额）
    else 已满或已接过
        API-->>FE: 业务错误
    end
```

| 页面 | 路径 | 说明 |
|------|------|------|
| 任务大厅 | `/hr/task-hall` | 本部门可接任务（未满员） |
| 任务管理 | `/hr/task` | 已接任务出现在「我负责的」 |

## 2. API 设计

### 2.1 接口列表

| 接口 | 方法 | 路径 | 描述 | AC |
|------|------|------|------|-----|
| 发布大厅任务 | POST | `/tasks/hall` | HR/经理；含 claimQuota | AC-001,002 |
| 大厅列表 | GET | `/tasks/hall` | 未满员开放任务 | AC-003 |
| 接取 | POST | `/tasks/{id}/claim` | 占一个名额 | AC-004,005 |
| 放弃 | POST | `/tasks/{id}/abandon` | 释放自己名额 | AC-006 |
| 强制收回 | POST | `/tasks/{id}/reclaim` | 单人或整单 | AC-007 |
| 评分 | POST | `/tasks/{id}/assignees/{empId}/score` | 复用 | AC-008 |
| 详情 | GET | `/tasks/{id}` | 扩展大厅字段 | AC-010 |

### 2.2 发布 POST `/tasks/hall`

```json
{
  "title": "string",
  "content": "string",
  "dueTime": "2026-09-10T18:00:00",
  "difficulty": 3,
  "claimQuota": 2,
  "suggestBonus": 200.00,
  "overduePolicy": "DEDUCT",
  "deductAmount": 50.00,
  "deptId": 2
}
```

* **鉴权**：仅 `HR_ADMIN` / `DEPT_MANAGER` + `feat.task.hall.publish`
* **校验**：`claimQuota` 为整数且 `1..20`（上限可配置）；`difficulty` 1..5；`DEDUCT` 时金额 > 0

### 2.3 接取 POST `/tasks/{id}/claim`

* 鉴权：`EMPLOYEE` + `feat.task.hall.claim`
* 成功响应含：`claimedCount`, `claimQuota`, `taskStatus`

### 2.4 放弃 / 收回

**abandon**：`{ "reason": "..." }` — 仅关闭/移除自己的 CLAIM assignee，重算是否回 OPEN。

**reclaim**：
```json
{
  "reason": "...",
  "action": "BACK_TO_HALL",
  "employeeId": null
}
```
* `employeeId` 有值：只收回该执行人名额  
* `null` + `BACK_TO_HALL`：清空全部认领，回开放  
* `null` + `CLOSE`：整单关闭并应用策略  

## 3. 数据库设计

### 3.1 修改 `hr_task`

```sql
ALTER TABLE hr_task
  ADD COLUMN claim_mode      VARCHAR(16)   NOT NULL DEFAULT 'ASSIGNED'
      COMMENT 'ASSIGNED指派 / OPEN大厅' AFTER priority,
  ADD COLUMN claim_quota     INT           DEFAULT NULL
      COMMENT '大厅名额：1独占，N协作' AFTER claim_mode,
  ADD COLUMN difficulty      TINYINT       DEFAULT NULL
      COMMENT '难度1-5' AFTER claim_quota,
  ADD COLUMN suggest_bonus   DECIMAL(10,2) DEFAULT NULL AFTER difficulty,
  ADD COLUMN overdue_policy  VARCHAR(16)   DEFAULT NULL
      COMMENT 'MARK_ONLY/ZERO_BONUS/DEDUCT' AFTER suggest_bonus,
  ADD COLUMN deduct_amount   DECIMAL(10,2) DEFAULT NULL AFTER overdue_policy,
  ADD COLUMN claimed_count   INT           NOT NULL DEFAULT 0
      COMMENT '当前有效认领数缓存' AFTER deduct_amount,
  ADD COLUMN version         INT           NOT NULL DEFAULT 0
      COMMENT '乐观锁' AFTER claimed_count;

CREATE INDEX idx_task_hall_open ON hr_task (claim_mode, status, dept_id);
```

> **不设单字段 `claimer_id`**：认领关系全部落在 `hr_task_assignee`；`claimed_count` 为缓存，以锁内实时 COUNT 为准并回写。

**OPEN 模式 status**

| status | 含义 |
|--------|------|
| 0 | 开放中（`claimed_count < claim_quota`，可接） |
| 1 | 进行中（已满员，或业务上已开始） |
| 2 | 已完成（全员完成） |
| 3 | 已关闭 |

### 3.2 `hr_task_assignee`

```sql
ALTER TABLE hr_task_assignee
  ADD COLUMN source VARCHAR(16) NOT NULL DEFAULT 'ASSIGN'
      COMMENT 'ASSIGN / CLAIM';
```

* 唯一键保持 `(task_id, employee_id)` → 天然防重复接取  
* 有效认领：`source='CLAIM' AND status IN (0,1,2)`（放弃/收回用 status=4 或 deleted）

### 3.3 扣款流水

```sql
CREATE TABLE hr_task_hall_deduct (
    id            BIGINT         NOT NULL AUTO_INCREMENT,
    task_id       BIGINT         NOT NULL,
    employee_id   BIGINT         NOT NULL,
    amount        DECIMAL(10,2)  NOT NULL,
    reason        VARCHAR(255)   DEFAULT NULL,
    deduct_month  CHAR(7)        NOT NULL COMMENT 'YYYY-MM',
    created_at    DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP,
    created_by    BIGINT         DEFAULT NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_task_emp_deduct (task_id, employee_id),
    KEY idx_emp_month (employee_id, deduct_month)
) ENGINE=InnoDB COMMENT='任务大厅未完成扣款（按人）';
```

### 3.4 权限 / 迁移

* `V21__task_hall.sql`：字段 + 表 + `feat.task.hall.claim` / `feat.task.hall.publish` + `page:/hr/task-hall`
* 超管不授 publish；EMPLOYEE 授 claim；HR/经理授 publish

## 4. 核心逻辑

### 4.1 接取（事务）

```
@Transactional
claim(taskId):
  empId = requireEmployeeId()
  assert EMPLOYEE && sameDept(task)

  task = selectByIdForUpdate(taskId)
  assert claim_mode==OPEN && status==0
  assert !existsActiveAssignee(taskId, empId)  // 或依赖 uk 捕获

  cnt = countActiveClaimAssignees(taskId)
  if cnt >= task.claimQuota:
    throw "名额已满"

  insert assignee(CLAIM, status=1, accept_time=now)
  cnt2 = cnt + 1
  task.claimedCount = cnt2
  if cnt2 >= task.claimQuota:
    task.status = 1   // 满员进入进行中，大厅不再展示
  task.version++
  update task

  log CLAIM; notify
```

也可用：

```sql
UPDATE hr_task
SET claimed_count = claimed_count + 1,
    status = IF(claimed_count + 1 >= claim_quota, 1, 0),
    version = version + 1
WHERE id = ? AND claim_mode = 'OPEN' AND status = 0
  AND claimed_count < claim_quota;
```

再 insert assignee；若 insert 因唯一键失败则回滚整单事务。

### 4.2 放弃

```
abandon(taskId, reason):
  lock task
  assignee = active CLAIM of current emp
  mark assignee closed/abandoned
  task.claimedCount = countActive(...)
  if task.status in (0,1) and claimedCount < claimQuota:
    task.status = 0  // 重新可接
  log ABANDON
```

### 4.3 主任务完成

* OPEN 模式：`claimed_count == claim_quota` 且所有有效 assignee `status==已完成` → 主任务 status=2  
* 未满员不允许主任务完成

### 4.4 关闭策略（按人）

| policy | 行为 |
|--------|------|
| MARK_ONLY | 关单 + 日志 |
| ZERO_BONUS | 未完成（或未评分）执行人 `score_bonus=0` |
| DEDUCT | 对每个 **未完成** 执行人 insert `hr_task_hall_deduct(amount=deduct_amount)` |

已完成且已评分者：不扣款、不清其奖金。

### 4.5 薪资

* `sumTaskBonus`：不变（按人完成+评分）  
* `sumTaskHallDeduct`：按员工+月汇总扣款，并入 `deduction`，备注标明

## 5. 异常处理

| 场景 | 提示 |
|------|------|
| 名额已满 | 任务名额已满 |
| 重复接取 | 您已接取该任务 |
| 跨部门 | 仅可接取本部门任务 |
| claimQuota 非法 | 协作人数须为 1～20 |
| 超管发布 | 没有权限 |

## 6. 安全与性能

* 列表：`claim_mode=OPEN AND status=0 AND dept_id=? AND claimed_count < claim_quota`
* 接取短事务持锁；`uk(task_id,employee_id)` 防重复

## 7. 验收标准映射

| AC | 实现 |
|----|------|
| AC-002 | DTO：`claimQuota` + difficulty + policy |
| AC-004/005 | 锁内 count < quota；quota=1 即独占 |
| AC-006 | abandon 释放名额并可能回 status=0 |
| AC-008/009 | 按人评分；按人扣款流水 |
| AC-011 | ASSIGNED 默认，原 API 不动 |

## 8. 技术决策

1. **名额字段 `claim_quota`**，不用单独「独占开关」——`1` 与 `N` 同一套逻辑。  
2. **认领落 assignee 表**，不用单 `claimer_id`。  
3. **扣款唯一键 (task_id, employee_id)**，支持多人各扣一笔。  
4. **一期须满员才算正式进行/完成**，避免「未招满却整单结束」歧义。

## 9. 风险与注意事项

* `claimed_count` 缓存必须与锁内 COUNT 一致，放弃/收回后回写  
* 上限 20 防误填过大名额  
* 建议奖金仍只展示，核算只认评分奖金  

## 10. 前端改造清单

* 发布表单：协作方式 — 「独占一人」/「多人协作」+ 人数输入  
* 大厅卡片：星级 + 「已接 x / 需 N」  
* 接取失败区分：已满 / 已接过 / 无权限  
* 详情：执行人列表与各人进度、评分
